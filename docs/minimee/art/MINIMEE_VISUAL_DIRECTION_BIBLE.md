# MiniMee Visual Direction Bible

This file defines the canonical visual identity for MiniMee image generation, gameplay art, entrance scenes and Interaction UI.

## Core identity
- Premium 16-bit pixel-art illustration.
- Child-first, warm, safe, curious, playful and collectible.
- Bright, rich, handcrafted scenes; never a sparse editor/tilemap look.
- Official gameplay camera: old-GTA-style high-angle top-down.
- Interior and exterior gameplay share the same camera family and sprite language.

## Environment language
Use dense but readable decorative detail: flowers, shrubs, vines, lamp posts, benches, fences, signs, banners, stalls, shelves, books, café props, crates, roof/window detail and scene-specific landmarks.

## Colour and lighting
Day: crisp, bright, warm, open, lush, cheerful.
Night: deep blue/purple ambience, warm windows and lamps, magical but still highly readable for children.
Rain/thunderstorm: geometry unchanged; use wet surfaces, puddles, umbrellas, canopies and atmospheric FX.
Festival Light: decorative event lighting only unless an approved manifest explicitly versions geometry/collision.

## UI language
UI must look embedded in the MiniMee world, not like generic SaaS. Prefer pixel-art wood, parchment, stitched paper, carved signboards, brass, toy-like icons, rounded tactile buttons and fantasy panels.

## Reference-image authority
Reference images may control mood, palette, craft level, decorative density, material feeling, character rendering, UI mood and entrance framing.
They may NOT override gameplay routes, doors, entrances, collision, scene-manifest coordinates, object IDs or global UI safe-area contracts.

## Forbidden drift
Avoid sparse plazas, generic farm-game visuals, generic medieval-RPG templates, flat editor tilemaps, unreadable dark nights, route-blocking clutter, building relocation between variants and generic web-dashboard UI.
